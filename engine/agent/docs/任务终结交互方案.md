# 用户终结任务交互方案

> 2026-09-17 · 基于 nn-bot/agent 现状勘察 · 状态:方案已验证可行,P0 已实施

## 1. 背景与问题

用户需要"终结任务"能力(终止运行中的任务/子任务)。现状勘察结论:

| 层 | 现状 | 位置 |
|---|---|---|
| WS 协议 | `TASK_NODE_STOP/STOPPED`、`TASK_NODE_PAUSE/RESUME`、`AGENT_STOP/STOPPED` 消息已定义 | `websocket/protocol.py:115-126` |
| 控制层 | **双重缺失**:TaskNodeControlHandler 从未注册(全仓库无实例化),且其 pause/resume/stop 实现全是 `success = True # Temporary placeholder`,真实调用与 WS 回执均被注释 | `websocket/handlers/task_node_control.py:131,166,217` |
| 执行层 | 真实现存在:cancel asyncio task + 状态置 ABORTED;对不存在节点幂等返回 True | `agentic/task_graph_excutor.py:1520,989`、`agentic/task_node_executor.py:1482` |
| Agent 级 | AGENT_STOP 在 chat.py 有完整实现(含"任务已结束"幂等处理、conversation_id 反查) | `websocket/handlers/chat.py:2820` |

即:前端发 TASK_NODE_STOP 无人处理——**假开关**。

## 2. 可行性验证结论(2026-09-17)

- ✅ 协议消息字段齐全:`TaskNodeStopMessage{task_node_id, reason}` → `TaskNodeStoppedMessage{task_node_id, reason, timestamp}`
- ✅ engine 获取路径:`user_workspace.execution_engine`(SSOT 挂载,`agentic/agent.py:752`);chat.py `_active_agents` 可遍历定位包含目标节点的 graph(task_node_id 为 uuid,跨工作区冲突概率≈0)
- ✅ 终态判断依据:`TaskNode.status`(TaskStatus 枚举)
- ✅ WS 回执通道:handler 基类 `send_message`(`websocket/handlers/base.py:106`)
- ✅ 取消后状态更新经 `_handle_task_cancellation` → `update_task_status` → 锁外 emit(2026-09-17 死锁修复模式),无循环等待
- ✅ 级联依据:TaskNode.child_ids + `_build_tree` DFS 已存在
- ⚠️ 风险:PENDING → ABORTED 的状态机转换合法性待运行验证(TaskValidator);非法时捕获降级为日志
- ⚠️ 两个 TaskStatus 枚举重复定义(`entity/task_types.py:32`、`async_task/types.py:24`),应合并(独立技术债,不阻塞本方案)

## 3. 交互设计

### 3.1 三种"终结"(意图不同,不混用一个按钮)

| 层级 | 意图 | 入口 | 确认 |
|---|---|---|---|
| L0 停止本轮生成 | 打断输出,任务可续 | 聊天框"停止"按钮(AGENT_STOP,已可用) | 无 |
| L1 终结单节点 | 该子任务不要了 | 任务树节点右键→终结(TASK_NODE_STOP) | 无(fast-fail) |
| L2 终结图/分支 | 全部停下 | 树根/分支菜单(TASK_NODE_STOP 级联) | 波及 ≥2 RUNNING 时二次确认 |

### 3.2 语义规则

1. **幂等 + 终态保护**:对 COMPLETED/FAILED/ABORTED 节点发 STOP → 返回 success + "已处于终态";重复 STOP 同样 success。节点不存在 → success + "任务不存在或已结束"(镜像 AGENT_STOP 幂等语义)
2. **CANCELLED vs ABORTED 拆分**(P1):CANCELLED=用户发起,ABORTED=系统中止。父任务凭此区分"可重试"vs"用户不让做"
3. **结果写 SSOT**(P1):终结时写 `node.data.result = "(用户终结: {reason})"`,父任务报告注入读到明确结果,不落"无显式完成结果"占位符,防盲目重试
4. **级联**(P1):终结节点 → DFS 递归取消所有非终态后代;反向不级联(父读报告自行决策,保 agent 自主性)
5. **new_task 等待方立即返回**(P1):父同步等 new_task 时子被终结 → 父 tool call 立即返回 error result,不等 60s 超时

### 3.3 UI 反馈

- 乐观更新:点击即置灰 + spinner → 收到 `TASK_NODE_STOPPED` 确认;3s 未确认回滚并提示"状态未知,可刷新"
- 终结节点:灰色 + 删除线 + "已终结(用户)" + reason
- 聊天流插系统消息"用户终结了任务 X(reason)",对用户和后续 LLM 轮次可见
- reason 可选输入,默认"用户请求终结";理由注入父对话供 LLM 理解(最有价值信号,不强制)

## 4. P0 实施记录(本次)

**改动最小化原则**:不注册新 handler(TaskNodeControlHandler 留作 P1 独立拆分),把 TASK_NODE_STOP 分发进已注册的 ChatHandler(已有 `_active_agents`/`send_message` 设施,与 AGENT_STOP 分支同构)。

- `websocket/handlers/chat.py`:
  - `get_supported_types` 增加 `MessageType.TASK_NODE_STOP`
  - `handle_message` 增加分支 → `_handle_task_node_stop`
  - 新方法 `_handle_task_node_stop`:遍历 `_active_agents` 定位含目标节点的 workspace → engine;
    - 终态/不存在 → 幂等回执
    - 运行中 → `engine.cancel_task_execution(node_id)`(CancelledError 路径置 ABORTED)
    - 未运行(PENDING 等)→ 直接 `task_graph.update_task_status(node_id, ABORTED)`,StateTransitionError 捕获降级
    - 统一发送 `TaskNodeStoppedMessage`

## 6. 已知风险

- 终结瞬间的写结果竞态:节点恰在 attempt_completion 写 result 时被 cancel → 以先完成者为准,幂等回执兜底
- 后台持久化(chat.py 2026-09-17 改动)在终结后需保证 final flush 落盘,否则恢复后任务"复活"(P2 审计项)
- 多工作区并发时 `_active_agents` 遍历为 O(n),n=活跃 agent 数,量级可忽略
