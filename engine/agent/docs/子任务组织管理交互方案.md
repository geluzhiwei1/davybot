## 0. 设计原则(一句话)

**结构留我们的图谱,交付学 Claude Code 的通道。**

- TaskGraph(持久化/可恢复/可视化)保留为组织 SSOT —— 这是产品差异点,优于竞品的一次性 subagent
- 结果交付改为 inbox 模式:**结果即返回值**(`node.data.result`),父不扫描子对话
- 事件发射路径必须**廉价、锁外、fire-and-forget**(subtask_events.py 已是此模式,推广为全局不变量)

## 2. 三视角交互模型

### 2.1 用户视角(UI 交互)

**任务树(组织呈现)**
- 实时状态/进度/深度/cost;节点点击展开:描述、result 摘要、事件时间线
- 节点操作菜单:终结(L1,已接线)、查看隔离会话(P2)、重跑(P2)、追问(P3)
- 树为**只读 + 干预**,不做手工拖拽编排 —— 结构由父 LLM 编排,避免用户手改图谱引发状态机/持久化复杂度(开放问题 §8)

**聊天流(过程可见)**
- 子任务生命周期摘要卡片(开始/完成/失败/终结/steered),默认折叠,点开看详情
- `[子任务执行报告]` 回注时渲染为结构化卡片而非裸文本
- 父的派发意图展示:"正在派发 2 个并行子任务…"

**干预**
- L0 停止本轮生成(聊天框停止按钮,已有)/ L1 终结单节点 / L2 终结分支(级联,P1)—— 详见任务终结交互方案.md
- 子任务 `ask_followup_question` → 用户在聊天流内直接作答(已有)

### 2.2 父 LLM 视角(agent 间协议)

**派发协议**(new_task 参数规范化,P1b):
- 必填:目标描述、**验收标准**(可判定)、上下文包(父只传必需,子不继承父全文)
- 可选:mode、`can_delegate`(默认 false=只许一层)、预算上限
- **广度上限**(双层,2026-09-17 补全):**图谱层**(SSOT 结构不变量)`TaskGraph.create_subtask` 锁内计数同父非终态(含 interactive)子节点,≥ `max_active_subtasks`(config,默认 3)→ raise `SubtaskBreadthLimitExceededError`(锁内原子判定,兜批量并行派发下工具层预检的 TOCTOU);**工具层** fast-path 图级在飞数 ≥ `max_concurrent_subtasks` → 同样拒绝(对齐 Claude Code 超限 spawn 直接失败、不排队);error result 携带活跃子任务 ID 列表 + "get_task_status 等待 / abort_task 释放"指引——防一轮爆量派发
- 派发即返回(task_id),**不同步等结果** —— 并行多子任务在同一轮工具调用里批量发出(P1b 提示词引导)

**结果协议**:
- 子完成 → `node.data.result` 写入(单一事实源)→ 报告回注父对话(inbox)→ 编排循环唤醒父
- **报告回显验收标准**:回注行 = 验收标准 + result + 成本/耗时;父据此判定"完成"vs"完成但未达标"——派发与交付闭环
- 子失败/被终结 → result 写明原因,父凭此决策重试/放弃,**不盲目重试**
- 超时 → 工具结果提示"先 `get_task_status` 再决定"(已实现;P1b 异步化后此提示随协议废弃)
- **预算耗尽语义**:子任务预算超限 → fast-fail,result 写"预算耗尽(已消耗 N)";父收到后不得同参数重派;用户侧 toast 提示

**状态协议**:`get_task_status` 为唯一查询入口;报告回注为唯一批量交付通道。

### 2.3 系统视角(不变量)

1. 图谱锁内**只做结构变更**,事件/持久化一律锁外(2026-09-17 修复模式)
2. 子任务默认**隔离会话**(P2-7 转正,P1a)——**必须与最小 steering 路径同批上线**(见 F7),否则用户运行中插话落入父对话、子任务永远看不到,隔离即交互黑洞
3. **终态 finalize 原子性**:进入终态的写路径(完成/失败/崩溃/终结/预算耗尽)必须**同笔写 status + result**——崩溃路径尤其要保证 failed 节点的 result 携带错误文本,否则报告落"无显式完成结果"占位符,父盲目重试(正是本方案要消灭的失败模式)
4. 层级:默认 1 层;`can_delegate=true` 的 mode 才允许二层(防派发树失控)
5. 事件 fire-and-forget,失败不影响主流程(subtask_events.py 模式)
6. 终态(COMPLETED/FAILED/ABORTED/CANCELLED)不可变更,一切操作幂等

## 3. 生命周期与操作矩阵

```
pending → running → (waiting_for_tool | interactive) → completed | failed | aborted
   │         │                                            ↑ 终态锁定
   └─────────┴→ aborted(用户终结/系统)          [cancelled:用户终结,P1 与 aborted 拆分]
```

| 状态 | UI 呈现 | 用户可操作 | 父 LLM 语义 |
|---|---|---|---|
| pending | 灰色等待 | 终结/无需确认 | 已受理未启动 |
| running | 蓝色+进度 | 停止生成/终结 | 进行中,勿重复派发 |
| waiting_for_tool | 蓝色+工具标签 | 终结 | 等工具返回 |
| interactive | 黄色+问题卡片 | 作答/取消追问/终结 | 等用户输入 |
| completed | 绿色+result 摘要 | 查看/重跑(P2) | result 可信,可汇总 |
| failed | 红色+错误 | 查看/重跑(P2) | 可重试(换策略) |
| aborted/cancelled | 灰删除线+原因 | 查看 | 用户终结→**禁止重试同目标**;系统中止→可评估 |

## 4. 关键流程时序

**F1 正常流**:用户消息 → 父 LLM `new_task`(含验收标准)→ 引擎建节点+隔离会话 → 子执行(事件流广播)→ `attempt_completion` 写 `node.data.result` → 报告回注父 → 编排循环唤醒父 → 父汇总/再派发(轮数上限内)→ 根 `attempt_completion` → 用户

**F2 并行流**(P1b):父一轮发 N 个 new_task(受广度上限)→ 引擎按 `max_parallel_tasks` 调度 → 全部到达终态 → 批量报告回注 → 父消费。**失败快速可见**:任一子失败即发 WS 事件,父不提前唤醒(屏障语义,KISS),但用户可见并可 L2 终结余下批次止损;部分屏障已落地为 wave 间依赖失败闸门(P3,2026-09-17:依赖 FAILED/ABORTED/CANCELLED → 后继节点不起跑直接 ABORTED,见 §6 P3 行),"失败即唤醒父决策"仍不做(提前唤醒只拿残缺结果列表,损大于益)

**F3 追问流**(已有):子 `ask_followup_question` → WS 问题卡片 → 用户作答/取消(followup_response/cancel)→ 子继续

**F4 终结流**(P0 已接线,L2 级联为 P1a):见任务终结交互方案.md;要点:父若在同步等 new_task → 子被终结时父工具调用**立即**返回 error result(P1a,不等 60s)

**F5 失败流**:子异常 → **终态 finalize 同笔写 status=failed + result=错误文本/类别**(不变量 3)→ 报告回注 → 父决策(重试需换策略,同参数重试应被提示词禁止)

**F6 恢复流**:checkpoint restore 图谱 → 非终态节点标记 resumable → 用户/父决定续跑或终结;终态数据只读

**F7 插话流 steering**(P1a 最小实现,与隔离转正同批):用户在子任务运行中发消息 → 路由器检测运行中子任务 → 追加 UserMessage 到对应隔离会话 + 发 `steered` 事件(subtask_events.py 已定义)→ 子下一轮消费;多条运行中 → 广播全部 + 聊天流提示"已注入 N 个运行中子任务"。P3 定向路由已落地(WS 消息带 `target_subtask_id` → 只注入该节点,§6 P3)

## 5. 与 Claude Code 模式对照(采纳/改造/保留)

| 竞品机制 | 决策 | 理由 |
|---|---|---|
| 结果即返回值,无会话扫描 | **采纳**(P1 收敛,扫描链降级为兼容历史) | 消灭"扫描扑空"整类缺陷 |
| 子上下文完全隔离 | **采纳**(P2-7 转正默认) | 共享对话是最大脆弱点 |
| 浅层级+能力白名单 | **已有等效**(can_delegate),维持 | — |
| 一轮并行派发 | **采纳**(提示词+调度) | max_parallel=2 可配置上调 |
| fire-and-forget 事件 | **采纳**(subtask_events 已是) | 死锁教训 |
| 一次性 subagent(无持久化) | **不采纳** | 图谱持久化/恢复/可视化是产品差异点 |
| 子无法回问父(只能最终汇报) | **不采纳** | 保留 ask_followup_question(人工协作场景需要) |
